Why is this an issue?

A ConstraintError is triggered when a cryptographic API is used with parameters that do not comply with security constraints defined in the CrySL rule. These constraints can apply to algorithm selection, key sizes, padding schemes, or cryptographic modes. Such an error indicates that the provided argument violates predefined security policies, which could result in weak encryption, predictable cryptographic outputs, or even insecure configurations that attackers can exploit.

How to fix it

The Signature API is being used with invalid parameters or in an incorrect order, violating the CRYSL rule for java.security.Signature.

Common misuses include:

  • Using unsupported or insecure algorithms (e.g., MD5withRSA)
  • Calling update() before initSign() or initVerify()
  • Providing incorrect offset and len values when working with byte arrays, causing out-of-bounds access

These issues can lead to runtime exceptions, signature failures, or cryptographic vulnerabilities.

To fix this issue, follow the correct usage order and ensure all parameters comply with the defined constraints.

Allowed Algorithms:

SHA256withRSA, SHA256withECDSA, SHA256withDSA, SHA384withRSA, SHA512withRSA, SHA384withECDSA, SHA512withECDSA

Correct Order of Operations:

  • getInstance()
  • initSign() or initVerify()
  • update()
  • sign() or verify()

Byte Array Constraints:
  • offset >= 0
  • len > 0
  • input.length >= offset + len
These ensure safe array access during signature operations.

Signing Example:
import java.security.*;

public class SignExample {
 public byte[] signData(byte[] input, PrivateKey privateKey) throws Exception {
 Signature signature = Signature.getInstance("SHA256withRSA");
        signature.initSign(privateKey);
 signature.update(input, 0, input.length);  // offset = 0, len = input.length
 return signature.sign();
    }
}

Verification Example:
import java.security.*;

public class VerifyExample {
 public boolean verifySignature(byte[] input, byte[] sigBytes, PublicKey publicKey) throws Exception {
 Signature signature = Signature.getInstance("SHA256withRSA");
  signature.initVerify(publicKey);
 signature.update(input, 0, input.length);
 return signature.verify(sigBytes);
}
}

Avoid:
  • Using offset or len values that exceed array bounds
  • Skipping init methods before calling update()
  • Using weak or unlisted algorithms
