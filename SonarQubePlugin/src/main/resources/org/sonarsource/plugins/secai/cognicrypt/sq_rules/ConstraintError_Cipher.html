Why is this an issue?

A ConstraintError is triggered when a cryptographic API is used with parameters that do not comply with security constraints defined in the CrySL rule. These constraints can apply to algorithm selection, key sizes, padding schemes, or cryptographic modes. Such an error indicates that the provided argument violates predefined security policies, which could result in weak encryption, predictable cryptographic outputs, or even insecure configurations that attackers can exploit.

How to fix it

A ConstraintError was triggered due to the use of invalid parameters or transformations in the javax.crypto.Cipher API. This means the current usage violates the defined CONSTRAINTS in the CrySL specification.

Common violations include:

  • Using a key type that is incompatible with the specified transformation
  • Using an unsupported algorithm, mode, or padding
  • Missing or invalid init() calls
  • Calling updateAAD() when it's disallowed
  • Providing incorrect offset or length values that cause array index violations
  • Failing to call getIV() when required by the mode

To fix this issue, ensure the Cipher instance and parameters comply with all defined constraints. Here are key guidelines based on the CrySL rule:

Key-Algorithm Matching:

  • If key is a SecretKey, then transformation must use one of:
    {AES, PBEWithHmacSHAxxxAndAES_xxx}
  • If using PublicKey, PrivateKey, or Certificate and encmode in {3, 4}, then transformation must be RSA

Algorithm, Mode, and Padding Combinations:
  • AES must use one of these modes: {GCM, CTR, CTS, CFB, OFB} and must use NoPadding
  • RSA:
    • mode == "" → pad == ""
    • mode == "ECB" → pad must be one of: NoPadding, PKCS1Padding, OAEPWithSHA-xxxAndMGF1Padding
  • PBEWithHmacSHAxxxAndAES_xxx must use PKCS5Padding

IV Requirements:
  • If mode is {CTR, CTS, CFB, OFB} and encmode == 1, then getIV() must be called
  • If encmode != 1, then init() must not use IV-related overloads

AAD Restrictions:
  • Only allowed when mode == GCM
  • Disallowed in modes: CTR, CTS, CFB, ECB, OFB

Offset/Length Constraints:
  • prePlainTextOffset >= 0, prePlainTextLen > 0, and prePlainText.length >= prePlainTextOffset + prePlainTextLen
  • plainTextOffset >= 0, plainTextLen > 0, and plainText.length >= plainTextOffset + plainTextLen
  • preCipherTextOffset >= 0 and preCipherText.length >= preCipherTextOffset
  • cipherTextOffset >= 0 and cipherText.length >= cipherTextOffset

Mode setting must be valid:
  • encmode must be one of: {1, 2, 3, 4}

Example Fix:
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;

public class AESExample {
 public byte[] encrypt(byte[] plainText) throws Exception {
 KeyGenerator keyGen = KeyGenerator.getInstance("AES");
 keyGen.init(256);
 SecretKey key = keyGen.generateKey();

 Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
 cipher.init(Cipher.ENCRYPT_MODE, key);
        return cipher.doFinal(plainText);
}
}

Avoid:
  • Using RSA with CTR or GCM
  • Setting incorrect offset and length values on byte arrays
  • Calling updateAAD() outside of GCM mode
  • Using mismatched Key types and algorithms
