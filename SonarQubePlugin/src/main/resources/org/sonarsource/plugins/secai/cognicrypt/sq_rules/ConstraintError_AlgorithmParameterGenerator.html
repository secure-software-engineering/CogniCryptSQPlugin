Why is this an issue?

A ConstraintError is triggered when a cryptographic API is used with parameters that do not comply with security constraints defined in the CrySL rule. These constraints can apply to algorithm selection, key sizes, padding schemes, or cryptographic modes. Such an error indicates that the provided argument violates predefined security policies, which could result in weak encryption, predictable cryptographic outputs, or even insecure configurations that attackers can exploit.

How to fix it

When passing an algorithm to the getInstance method, the algorithm has to be one of the following:

  • AES
  • Camellia
  • Shacal2
  • Shacal-2
  • DH
  • DiffieHellman
  • DSA
  • ElGamal
For the init method there is a choice between using an int to convey the size or using an AlgorithmParameterSpec object. When using the former, depending on the algorithm chosen a specific size has to be used.

Use size 3072 for the following algorithms:
  • DH
  • DiffieHellman
  • DSA
  • ElGamal
Use size 128, 192 or 256 for the following algorithms:
  • AES
  • Camellia
  • Shacal2
  • Shacal-2
