Why is this an issue?

A ConstraintError is triggered when a cryptographic API is used with parameters that do not comply with security constraints defined in the CrySL rule. These constraints can apply to algorithm selection, key sizes, padding schemes, or cryptographic modes. Such an error indicates that the provided argument violates predefined security policies, which could result in weak encryption, predictable cryptographic outputs, or even insecure configurations that attackers can exploit.

How to fix it

A new MessageDigest is created not through a constructor but by calling one of the following:

digest.getInstance(String algorithm);
digest.getInstance(String algorithm, Provider provider);
digest.getInstance(String algorithm, String provider);

The algorithm must be one of:

  • SHA-256
  • SHA-384
  • SHA-512

While the update method can be called with different sets of parameters, when called as follows:
digest.update(byte[] preInput, int offset, int len);
these contraints have to be fulfilled:
  • length(preInput) >= offset + len
  • offset >= 0
  • len > 0
Similarly, while there are different ways to call digest, when using it as follows:
digest.digest(byte[] output, int outOffset, int outLen);
the constraints to be fulfilled follow the same line:
  • length(output) >= outOffset + outLen
  • outOffset >= 0
  • outLen > 0
