Why is this an issue?

An OrderError is reported when a cryptographic operation is not fully completed as expected (IncompleteOperationError) or executed in the wrong order (TypestateError). CrySL rules define a specific order of operations (e.g., an encryption process requires initialization before performing encryption, followed by finalization). If a required step is missing or in the wrong place, the cryptographic process may remain incomplete, potentially leading to unencrypted data, insecure partial outputs, or unexpected runtime failures. This error ensures that cryptographic workflows are executed in their entirety and in their intended sequence to maintain security.

How to fix it

The following operations must be executed in the correct order:

  1. Get a SecureRandom object:
    • new SecureRandom
      • new SecureRandom()
      • new SecureRandom(byte[] seed)
    • getInstance
      • SecureRandom.getInstance(String algorithm)
      • SecureRandom.getInstance(String algorithm, String provider)
      • SecureRandom.getInstance(String algorithm, Provider provider)
      • SecureRandom.getInstance(String algorithm, SecureRandomParameters params)
      • SecureRandom.getInstance(String algorithm, SecureRandomParameters params, String provider)
      • SecureRandom.getInstance(String algorithm, SecureRandomParameters params, Provider provider)
      • SecureRandom.getInstanceStrong()
  2. set seed and get next [optional, can be called more than once]
    1. setSeed [optional]
      • random.setSeed(byte[] seed)
      • random.setSeed(long seed)
    2. End [optional, can be called more than once]
      • generateSeed
        • byte[] seed = random.generateSeed(int numBytes)
      • next
        • random.nextBytes(byte[] bytes)
        • random.nextBytes(byte[] bytes, SecureRandomParameters params)
        • random.next(int numBits)
